开发设计稿 · 2026-10-08 · v1.0

拾景：Windows 静态壁纸软件
详细开发方案

定位：免费开源、Windows 优先、WinUI 3 原生界面。每天给用户一张推荐壁纸，支持保存原图、一键设置桌面，以及导入自己的图片与图源。项目名“拾景”为临时工作名。

路线结论：新建 C# / WinUI 3 应用，使用本地服务层与 SQLite；借鉴现有项目的下载、图源适配和 Windows 接口实现。首版围绕静态图片闭环开发，默认无需云服务。界面以“图库导航”为主布局，将“沉浸预览”作为详情体验。本文保存实施前的设计；当前初版实现、测试与限制以 项目状态 为准，完整计划不等于全部功能已交付。

1. 范围与版本边界

采用 Windows 11 主体验、Windows 10 22H2 兼容验证的目标。兼容范围必须以具体 SDK、打包方式和实机结果确定，不把“能安装”视为“全部功能兼容”。首版 x64，ARM64 后续加入。只处理静态 JPEG、PNG、BMP；WebP 在确认 WIC 解码能力后作为扩展，不在首版宣称全平台支持。

版本包含功能完成标准
P0：可发布核心今日推荐、近期记录；发现和本地搜索；收藏；保存原图；设置桌面；显示器选择；本地文件/文件夹导入；HTTPS 图片直链；受限 JSON 清单；图源开关和诊断；主题、存储和缓存设置“推荐 → 预览 → 保存 → 设为桌面”以及“导入 → 设为桌面”闭环可用；断网仍能使用已有原图。
P1：使用体验增强用户主动开启的每日自动更换；托盘；启动/睡眠恢复补偿；在线图源关键词搜索；高级裁剪和每屏独立适配；导入/导出配置；ARM64自动任务不覆盖当天用户手动设置；多屏变更有明确结果与恢复入口。
后续候选Commons 精选合法授权图库、更多内置适配器、MSIX/Store、局域网图库每个来源单独验证条款、接口和内容质量后加入。

首版不包含动态壁纸、账户、云收藏、广告、订阅、评论、AI 推荐服务和锁屏自动设置。截图中的这些入口是视觉参考，并不自动转化为产品需求。

2. 前端 UI 预览与 WinUI 实现

2.1 两种布局的取舍

图库导航：固定主导航、明确页面标题、今日大图、近期卡片、发现网格。适合频繁筛选、收藏与管理图源，作为默认主界面。沉浸预览：图片占主要区域，标题与操作浮层集中在下方，适合欣赏与设置桌面；生产版放在详情页/全屏模式中。两者共用 ViewModel 和业务服务，不维护两套业务逻辑。

本次可交互预览包含“今日推荐、发现壁纸、我的图库、图源管理、设置”五页，以及详情、导入、添加图源对话框。可体验搜索/筛选、收藏、下载进度与取消、图源启用、主题、显示器与适配选择、离线状态。下载、连接测试、导入和设置桌面为本地模拟；不会读取用户文件或调用 Windows 壁纸接口。预览固定日期及尺寸、作者、图源映射均为示例数据。

预览图片取自 WinDynamicDesktop 仓库内的 Apple 桌面素材，用于布局说明；它们不是 Bing/Wallhaven 的真实搜索结果，也不证明图片达到所标尺寸。正式应用必须替换为用户提供或已确认授权的素材。外部图片无法加载时，仍可查看界面和交互。

2.3 视觉规范

排版
Segoe UI / 系统中文回退；正文14 DIP，辅助12 DIP，页标题28 DIP，图片标题20 DIP；200%文本缩放单独验证。
布局
8 DIP间距系统；内容内边距24；卡片圆角12；展开导航约208；窄窗口仅图标/顶部导航。
交互
蓝色主操作；同组一个主按钮；明确禁用与进度；键盘焦点可见；支持减少动画。

默认窗口建议 1180×800 DIP、最小 720×540 DIP。大于 1100 使用展开导航和三列图库，900–1100 两/三列按实际卡片最小宽度计算，720–900 收起导航与两列卡片。生产桌面最小宽度与对话中的窄屏预览是不同约束，不通过缩小字体挤压内容。适配100%、150%、200% DPI及跨屏移动。

应用壳优先 Mica，内容卡片使用不透明/高对比可读表面。需要模糊应用内部大图时使用适度 Acrylic；Mica 不是实时模糊预览图的工具。避免在大图库持续使用昂贵实时效果。高对比模式关闭装饰材质，使用系统颜色；图标用 Fluent 字形，按钮都有可访问名称。

3. 功能流程与异常反馈

动作成功流程失败或中断
启动应用迁移数据库 → 修复上次中断任务 → 读取当天推荐 → 后台刷新元数据 → 显示缓存预览单源失败不阻塞其他图源；首次无内容引导导入；数据库迁移失败保留备份并提供恢复入口。
保存原图解析原图地址 → 获取/复用原图 → 文件校验与落盘 → 系统保存对话框选择导出文件 → 复制原字节 → 显示打开位置取消对话框不记录导出成功；磁盘满/拒绝访问提供选择目录；原图缓存成功但导出失败区分显示。
设为壁纸选择目标 → 获取原图 → 准备应用文件 → 保存原状态 → COM应用 → 记录逐屏结果原图下载失败不触碰当前壁纸；显示器断开/部分应用失败显示逐屏状态并可重试或恢复。
添加图源选类型 → 输入路径/HTTPS地址 → 验证 → 测试 → 展示样本和数量 → 保存启用 → 同步格式错误定位字段；连接失败允许保存为停用状态；重定向/地址过期/429给出可行动结果。
本地导入文件选择或拖放 → 解码校验 → 复制到托管目录 → SHA256去重 → 入库 → 生成缩略图单个坏图不阻塞批次；显示导入/重复/失败数量；源目录删除后托管副本仍可用。
收藏写入收藏记录 → 卡片与图库同步；已存在原图保持留存策略收藏只存元数据不会偷偷下载原图；写库失败恢复按钮状态并提示。
删除/清理清预览缓存仅删除可再生成缩略图；删除托管原图需要单独明确动作当前桌面及恢复快照引用的文件受到 pin 保护；不存在文件只修复索引，不误报成功删除。

预览将“保存原图”合并为模拟保存。生产实现必须区分“应用内部下载”和“导出到用户选择目录”；“设为壁纸”只需要内部下载，不弹出保存对话框。图库中“已下载”代表内部原图可用，导出记录只是外部文件路径记录。

错误码统一映射为中文提示：Offline、RateLimited、AuthRequired、UrlExpired、InvalidImage、FileTooLarge、DiskFull、AccessDenied、SourceUnavailable、MonitorDisconnected、DesktopApplyFailed、DatabaseFailed。日志保留诊断信息，界面给出“重试、选择目录、查看已下载、停用图源”等实际操作。

目标使用 .NET 10 LTS、稳定 Windows App SDK、CommunityToolkit.Mvvm、Microsoft.Extensions.DependencyInjection / Logging / Http、Microsoft.Data.Sqlite。具体依赖版本在第一个里程碑核对并锁定，采用 Central Package Management 与 lock file；不在设计文档中把动态的“最新版”作为固定依赖。SQLite 访问优先显式SQL与小型仓储，复杂统计出现前不引入EF迁移负担。

6. 图源路线与自定义图源规范

来源开发安排能力与限制
本地文件/文件夹P0必须，作为离线基线文件选择、递归可选、限制符号链接循环、分批扫描、增量去重。FileSystemWatcher事件合并；溢出后重新扫描，不将每个事件视为最终状态。
HTTPS图片直链P0必须一次解析一张图片；定期刷新可选；类型、重定向、字节和解码校验；不执行远端脚本。
JSON清单P0必须最稳定的用户扩展能力；明确协议版本、限制条目数和大小；清单只有数据，不下载插件代码。
Bing每日图P0可选适配器；发布前条款核验社区使用HPImageArchive；地区、日期、原图可用性可能变化。仅当实际取得并解码到足够尺寸才标UHD；“请求_UHD”不能证明获得UHD。默认启用与分发策略在发布前确认。
WallhavenP0可选浏览适配器，P1在线搜索只请求SFW；保留作者和原页链接；API密钥由用户自带并安全保存。官方帮助页此前调研受403限制，实际配额、字段及国内网络体验需要联调核验，不能承诺固定限额。
Wikimedia CommonsP1/P2精选列表优先固定类别/策展清单；Imageinfo元数据保留具体许可、署名与来源。不同图片许可不同，不统一称“无版权”。
Unsplash / Pexels排除官方API内置壁纸供给路线官方API规则限制壁纸用途/竞品式用途；不因“免费图片”就认为可以搭建同类壁纸产品。

6.2 适配器生命周期

每个适配器声明能力，页面根据能力显示筛选/搜索入口，避免所有图源强行使用一套参数。同步只更新元数据与按需预览；原图用户触发时下载。移除图源采用软删除：已收藏、已下载和当前桌面保持可用，新推荐与同步排除该源。P0扩展方式是数据图源；新网站需要开发者增加编译期适配器。

download_jobs / export_records可恢复任务和用户导出记录分开；同variant最多一个活动下载；导出文件不归缓存清理所有。

app_settings版本化设置JSON；单项验证，默认值兼容；不保存明文密钥。

8. 下载、保存、缓存与任务状态

Queued → Resolving → Transferring → Verifying → Committing → Completed
   任意允许阶段 → Cancelled / Failed（错误码、重试次数、重试时间）

Acquire流程：命中ready原图 → 直接返回
否则：重新解析地址 → 流式下载.part → 校验类型与解码 → SHA256
    → 移动托管文件 → 事务更新asset/job → 返回LocalAsset
Export流程：LocalAsset → 用户选目标 → 同目录临时复制 → 原子提交 → 导出记录

HttpClient由IHttpClientFactory管理，使用ResponseHeadersRead流式写盘；不把整个原图放进byte[]。默认全局原图并发2、预览并发4、解码并发2，均为待压测的初值。总超时与无数据超时分开；CancellationToken传到网络、文件和校验。取消后清理.part与job状态；只有最终提交完成才显示100%和成功。

重试限网络暂时失败、408、429、部分5xx，最多3次并指数退避加抖动；尊重Retry-After。401/403需要用户操作，404/失效签名先重新解析一次，磁盘不足/坏图不盲重试。首版中断后重新下载；P1仅在服务器支持Range、ETag/If-Range且本地部分文件匹配时续传。

同一原图的重复请求共享任务。每个调用方可取消自己的等待；只有全部消费者取消才停止共享下载，防止关闭详情页取消了“设为壁纸”正在依赖的任务。跨进程活动下载用数据库唯一索引和互斥锁共同保护；退出时执行受限时长的取消与状态落盘。

下载前检查状态码、Content-Type与Content-Length；下载过程中继续限制累计字节；下载后检查文件签名与实际解码像素，识别返回HTML的“图片地址”和截断文件。远端文件名不能决定本地路径。原图按哈希命名、保留原字节，不重新压缩。

缩略图使用LRU、默认1GB上限；原图另显示占用并提供明确管理，首版不自动删除用户主动下载/导入的原图。当前应用文件及恢复窗口内文件pin保护。应用文件只在下次成功替换并确认没有其他屏幕引用后解除pin；恢复快照最多保留最近一次或设定期限，避免无限占用。

9. Windows桌面与多显示器实现

采用 IDesktopWallpaper，在独立STA线程创建与使用COM实例。SetWallpaper接收本地完整路径与显示器设备路径；monitorID为NULL时可统一设置所有屏幕。每次应用前重新枚举显示器，不能仅依据旧的“屏幕2”编号。

关键限制：SetPosition不接收monitorID，适配方式是全局设置。首版允许各屏选择不同图片，但“填充/适应/居中/跨屏”会统一影响屏幕；界面必须明确说明。“跨屏”选择时目标强制为所有显示器。每屏不同裁剪方式作为P1，预先生成对应屏幕像素尺寸的派生图再应用，原图独立保存。

  1. 解析目标设备路径、验证仍连接；获取真实原图并读取尺寸、EXIF方向。
  2. 准备系统可读JPEG/PNG应用文件，必要时将不受稳定支持格式转为派生文件。透明PNG合成到明确背景色；不改动原始文件。
  3. 读取现有每屏路径与全局position，创建apply_run、apply_targets及pin，写入待操作状态。
  4. 串行设置全局position与各目标屏幕的本地文件，记录HRESULT/逐屏结果。
  5. 全部成功则提交当前桌面状态；部分失败显示具体屏幕与恢复按钮。恢复先恢复全局position及受影响各屏路径。
  6. 日志与UI将恢复失败单独标记；Explorer重启/外部桌面工具切换后按系统实际状态重新对账。

这不是Windows提供的原子事务：其他程序可能同时修改壁纸，原路径可能不可读，显示器可能热拔插。因此恢复是尽力执行，不承诺百分之百还原。仅在已知旧文件仍可用时显示恢复可用；按实际成功屏幕报告，不显示误导性的“所有屏幕已完成”。COM接口定义、HRESULT和字符串内存释放必须审查。

P0验证桌面设置；锁屏走另一套API与能力检查，后续单独设计，不把桌面成功推断为锁屏也成功。兼容回退到SystemParametersInfo时明确只有全局简单设置，不能伪装多屏成功。当前用户桌面操作无需管理员权限。

10. 每日推荐与P1自动更换

每日推荐是内容选择；每日自动更换是独立、用户选择开启的桌面操作。首版推荐默认不会修改桌面。每日推荐由本地策略实现，不需要AI或服务器：当前启用图源 → 合适候选 → 排除不适合/近期重复 → 日期稳定选择 → 持久化。

  1. 启动先查询当前用户本地日历日期的daily_selection。存在且条目可用则返回，刷新页面不更换。
  2. 不存在时从启用且未删除图源收集候选：Bing按来源日期，其他源按质量/横竖比/历史去重。原尺寸未知可候选，但不显示虚假高清标签。
  3. 优先匹配主屏比例与足够分辨率的图片；排除最近30天已推荐项，候选不足时逐步放宽并记录reason。
  4. 一次事务写入唯一日记录；并发创建遇冲突后读取已有结果。随机选择器带可测试种子，但最终记录是事实来源。
  5. 断网时使用已下载/本地候选；仅缓存到旧推荐时明确显示“最近可用”，不称为今天的Bing图。
  6. “换一张”是显式操作，更新同日revision；浏览其他图片详情不修改今日推荐。

系统时间回拨时保留已记录日期选择，检测异常并在重新进入正常日期后再评估。跨时区根据本地日历日期处理，time_zone_id只作审计，不能作为当日唯一键的一部分。首次无内容显示导入入口，而不是无限加载。

P1后台策略

推荐独立的一次性Worker配合当前用户Task Scheduler的登录/每天触发器；登录后的后台运行必须在交互用户会话，不用SYSTEM设置其他人的桌面。不要依赖关闭后的应用内Timer。Worker调用共享用例，执行后退出；休眠后启动时比较最后执行日期，合并补偿一次，不补执行多天历史任务。

自动开关默认关闭，用户开启时注册任务；关闭/卸载删除任务。二进制安装在稳定位置，升级不留下失效路径；参数正确引用带空格路径。主应用与Worker共享锁。当天手动设置成功后记录ManualOverride(local_date)，自动更换跳过当天；失败不能标记override。电池/计费网络策略可设为“只使用已有原图”，无合适内容则静默跳过并记录原因。

11. 高清、性能与可靠性目标

高清来自真实原图、适配算法与显示策略。以实际解码宽高显示尺寸；4K/UHD标签须有明确阈值，3840×2160只是16:9示例，竖屏用实际尺寸说明。小图放大只提示“原图低于屏幕分辨率”，不称提升到4K。保存原字节，设置桌面用派生图，避免多次有损编码。

一张3840×2160 BGRA解码约31.6MiB，100张约3.09GiB，不能把整个图库的原图全部解码到内存。图库按卡片可见宽度×DPI生成/解码缩略图；数据分页与UI虚拟化都需要，使用GridView时避免外层ScrollViewer破坏虚拟化。详情仅保留当前图及小量预取，离开页面释放不再使用的Bitmap。
