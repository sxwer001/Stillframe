# 桌面壁纸持久恢复

核验：2026-11-04；独立修复分支实现与替身检查完成，只读COM探测完成，真实桌面设置/回滚未执行。本批没有更改版本、安装包、真实图库或系统壁纸。

## 状态机

`desktop-recovery-v1.json`与图库同根，独立于SQLite设置。记录版本、Original最初外部状态、Expected应用预期状态，以及未完成操作的Before快照；包含原图路径、活动显示器设备标识、全局显示方式、背景色及幻灯片状态。先写唯一临时文件、Flush(true)、原子替换，成功后才调用系统。记录不能写入、格式损坏、未来版本或链接路径均停止变更。快照路径属于本机用户数据，不上传、不写诊断日志。

1. Capture完整旧状态，校验目标和可恢复的原图。当前仅支持启用的静态图片；幻灯片、禁用背景或旧文件不存在时拒绝设置，不以静态快照冒充完整系统个性化备份。Windows聚焦/主题模式的完整恢复不在当前保证范围，仍需实机核验。
2. 原子提交Before+Expected意图；复核系统仍与Before一致，然后设置全局方式、逐屏壁纸，读回一致后提交完成状态。
3. 任一设置、读回或完成写盘失败：尝试比较后回滚到本次Before。异常即使提前抛出也不能丢掉已落盘意图；无法完整回滚时保留记录，并阻止新操作覆盖它。
4. 启动只加载恢复入口，不自动修改系统。用户点击恢复后逐屏核对：当前路径必须仍等于应用预期或未完成操作的Before；用户后来修改的路径/模式/背景色或状态不覆盖。失联设备/缺失原图保留待恢复。
5. 先恢复图片；只有所有相关设备均存在、没有额外未受管设备且全局状态仍匹配，才恢复全局显示方式。整份状态读回一致才删除记录。显式“放弃恢复记录”需原生确认，只删清单，不修改系统或任何图片。

连续更换仍保留同一链条最初的Original；可加入新显示器并保留已断开设备的引用。用户在系统设置中更换后又主动在拾景应用新图片时，以该外部状态开启新链条，避免旧记录覆盖新选择。由于[IDesktopWallpaper](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-idesktopwallpaper)没有比较并交换的原子事务，对其他程序同时写入以及把状态恰好改回相同值的情况不能绝对区分；每次写入前重读来缩小竞态，不承诺原子多屏回滚。

COM对象只在单次STA内使用，服务入口串行。活动设备筛选排除shell保留的已断开设备记录，保留GetMonitorRECT的S_FALSE，不把读取失败当虚构“所有显示器”。[GetStatus](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-idesktopwallpaper-getstatus)提供幻灯片状态，[SetWallpaper](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-idesktopwallpaper-setwallpaper)逐屏写入；全局SetPosition的恢复必须受整组状态保护。
